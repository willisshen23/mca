## 1. 背景与定位

项目需编写《功能说明书》，作为**行内交付验收**文档。已确认的关键决策：

- **用途/受众**：交付验收，措辞正式，功能点可逐条对照系统演示；
- **格式**：无行内强制模板，按银行交付文档惯例（封面、修订记录、正式章节编号、自动目录），最终输出 Word；
- **范围**：全系统功能，与《需求说明书》功能范围对齐；
- **粒度**：截图 + 操作级（功能描述 / 界面截图 / 操作步骤 / 输入输出 / 业务规则与约束）；
- **组织方案**：方案 A —— 按功能模块划分章节，另加"典型业务流程"一章，与需求说明书功能需求逐条映射。

已排除项（用户确认不做）：附录"功能点验收对照表"不做；"外部接口说明"章节暂不做。

## 3. 功能点统一模板

每个功能点（3.x / 4.x … 小节）按统一结构编写：

| 要素 | 说明 |
|---|---|
| 功能编号 | `F-<模块>-<序号>`，如 `F-CHAT-01`，全文档唯一 |
| 功能描述 | 一段话说明该功能做什么 |
| 界面截图 | 实际系统截图，带图编号（如"图 3-1 对话主界面"），存入 `docs/功能说明书/images/` |
| 操作步骤 | 编号步骤，可被验收人员照着操作 |
| 输入/输出 | 表格（输入项、来源、约束；输出/结果展示） |
| 业务规则与约束 | 逐条列出，如"同一会话同时仅允许一个运行中任务" |

模块编号约定：CHAT（对话交互）、ACT（活动与队列）、RPT（报告）、HITL（审批）、SKILL（技能）、TPL（模板与提示词）、HIST（历史与日志）、SYS（系统管理）。

## 4. 编写与产出流程

1. **功能点清单核实**：以《需求说明书》功能需求为骨架，对照后端 `backend/src/api/routers/` 与前端 `frontend/src/views/` 核实实际已交付功能，只写已实现的功能点；
2. **截图采集**：启动 backend + frontend + mock 服务，用 Playwright 截取各界面真实截图（含审批卡片、报告预览等关键状态），统一命名存入 `docs/功能说明书/images/`；
3. **正文编写**：Markdown 编写，功能点按第 3 节模板与编号约定；
4. **Word 转换**：Pandoc + reference.docx 模板转 Word（封面、修订记录、自动目录、图表编号样式）；
5. **一致性校对**：功能点与需求说明书逐条映射核对，确保无遗漏、无超出。
