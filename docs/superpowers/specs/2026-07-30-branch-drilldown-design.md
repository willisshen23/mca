# 分行活动分析报告：支行机构对比下钻设计

> 日期：2026-07-30
> 状态：已获用户批准（头脑风暴结论）
> 范围：报告管线（report_pipeline），v2 唯一运行时生效

---

## 1. 需求

分行活动分析报告中，如果某一个分行的参与活动人数占总参与人数的 **95% 及以上**，说明分行间对比已失去区分度。此时报告不再展示分行间对比，改为展示**该分行下属支行的机构对比**。

## 2. 已确认的关键决策（用户拍板，勿重新讨论）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 支行级数据来源 | **现有接口同一请求已返回**支行级数据，后端只需解析使用，无需新增接口或参数 |
| 2 | 适用范围 | **任意含「所属分行」分段的报告**，不限于特定模板 |
| 3 | 对比指标 | 参与人数 **+ 报告中已有的其他指标**——触发后该模块下所有按分行分段的指标统一切换为支行维度 |
| 4 | 展示方式 | **替换**分行对比（不新增章节），原分行对比位置直接变为支行对比 |
| 5 | 参与人数口径 | 指标名称**模糊匹配**：indexName 含「参与」且含「人数/客户数」 |
| 6 | 阈值 | ≥95%（含恰好的 95%） |

## 3. 方案选型

- **方案 A（采纳）：后端确定性节点**。在报告管线取数之后新增 `branch_drilldown` 能力节点，纯 Python 完成判断与数据替换；LLM 合成节点不改动，只渲染自己看到的数据。判断与计算确定性、可单测，与近期"防凭空捏造数据"方向一致。
- 方案 B（否决）：提示词驱动，让 LLM 自行判断 95% 条件并切换数据。LLM 做算术判断不可靠。
- 方案 C（否决）：前端渲染时替换。报告是后端生成的 HTML，前端无结构化数据。

## 4. 设计

### 4.1 插入位置

新节点 `branch_drilldown_node`（`backend/src/report_pipeline/capabilities/branch_drilldown.py`），在 `backend/src/agent_v2/tools/report_gen.py` 的管线序列中插于：

- `component_value_cleanup` 之后（在已清洗的数据上工作）；
- 外呼数据合并（`_merge_outbound_into_component_values`）之后（在最终 component_values 上工作）；
- `marketing_report_synthesis` 之前。

上传文件分支（`uploaded_component_value_extract`）产出的 component_values 走同一位置，天然一并覆盖。

### 4.2 触发判断

对 `component_values` 中每个含「所属分行」维度（plateRuleCfgInfList 内 cfgTypeCd=1 且 indexName 含「分行」的条目）的模块/指标组：

1. 在该维度组内按 §2-5 的模糊规则定位「参与人数」指标；
2. 将该指标的 resData 按分行汇总 `totalCount`（跨其他维度，如性别，累加同一分行的所有行）；
3. 计算各分行占比；若某分行占比 ≥ 95%，触发，记该分行为「主导分行」。

判断对每个含分行维度的模块独立进行；一份报告可能有多个模块各自触发或不触发。

### 4.3 替换逻辑（触发后）

对被触发模块下的**所有指标**（不止参与人数）：

1. 维度配置中「所属分行名称」条目替换为支行维度条目（按 indexName 含「支行」在接口返回中定位）；
2. resData 替换为支行级数据行，且**仅保留主导分行下属支行**的行；
3. 在触发的模块（plate）dict 上写入 `branchDrilldownNote` 字段：「XX分行参与活动人数占全行XX%（≥95%），本模块原分行对比已替换为XX分行下属支行机构对比。」该字段随 report_data 原样进入合成提示词，LLM 可见，使报告读者知道口径变化（不注入 display_requirement——它派生自活动模板匹配结果，与数据模块无可靠映射）；
4. 在 state 中记录 `branch_drilldown_result`（触发的模块、主导分行、占比），供日志与前端/调试用。

### 4.4 兜底

以下任一情况保持原样、仅记日志，不影响报告生成主流程：

- 接口返回中找不到支行维度或支行级 resData 为空；
- 找不到可匹配的「参与人数」指标；
- 参与人数总计为 0（避免除零）；
- 所有分行占比均 < 95%（正常情况，不触发）。

节点本身不抛异常中断管线；任何未预期错误捕获后按"未触发"处理并记 warning 日志。

### 4.5 数据结构假设（实施时验证）

模板详情接口返回（见 `mock/通过分析模板 id 、活动 id、时间范围获取分析模板详情及活动数据api/`）中：

- 维度条目：`plateRuleCfgInfList` 内 `cfgTypeCd="1"`，`indexName` 为「所属分行名称」（indexNo 如 I200174）；支行维度同构（indexName 含「支行」）；
- 数据行：`resData` 按维度 indexNo 键控（如 `{"I200174": "南京分行", "I200176": "男", "totalCount": 38}`）。

实施第一步需用真实/最新接口返回验证支行维度条目的确切 indexName/indexNo 及 resData 形态；若与假设不符，调整定位规则，整体设计不变。

## 5. 测试

pytest（`backend/tests/`，新增 `test_branch_drilldown.py`）覆盖：

1. 某分行占比 >95% → 触发，该模块全部指标切换为支行维度且仅含主导分行下属支行；
2. 恰好 95% → 触发（边界）；
3. 最高占比 <95% → 不触发，数据原样；
4. 支行维度/数据缺失 → 不触发，保持原样；
5. 无参与人数指标可匹配 → 不触发；
6. 参与人数总计为 0 → 不触发；
7. 多指标模块：触发后所有指标同步切换（不只参与人数）；
8. 多模块报告：各模块独立判断，互不影响。

## 6. 非目标（YAGNI）

- 不做阈值可配置化（95% 写死为常量，后续有需求再提配置）；
- 不改动 LLM 合成提示词主结构（仅注入一句口径说明）；
- 不改前端；
- 不做"下钻后同时保留分行对比"的双展示模式。
